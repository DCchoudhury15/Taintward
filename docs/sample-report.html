9. Method and limits

How the data is produced: each tool call made through Taintward is recorded as an OpenTelemetry span. The SDK or gateway detects sensitive data, carries a taint label along the run, and redacts the input before it reaches an outside destination. The Taintward collector evaluates a Rego policy on every span and records the decision (taintward.policy.*). This report reads those spans back and counts them. It does not call any LLM.

What this report does not show:

  • The report covers only calls made through Taintward (SDK wrappers, framework adapters or the MCP gateway). Calls that bypass it are not recorded and not counted.
  • Sensitivity comes from Taintward's detectors (Presidio and secret patterns) plus the taint carried along each run. A value the detectors do not recognize is not counted as sensitive.
  • The raw value check reads the input as recorded on the span. For SDK calls this is the input after the redaction gate, the same value the destination received. For the MCP gateway, arguments listed in passthrough_args are forwarded unchanged but stored masked on the span, so they cannot be checked here; review that list separately.
  • Calls in audit-only mode forward data without redaction. When such a call carried sensitive data, the report does not make the "0 raw values" statement.
  • The numbers are only as complete as the trace store. Sampling, retention limits or dropped spans reduce what is counted. The evidence log and its signed checkpoints show that recorded violations were not changed or removed later; they do not prove that every call was recorded.
  • Jurisdictions come from the destination configuration (taintward.jurisdiction). A transfer flag means the policy marked that jurisdiction as not adequate for personal data and the call was part of a run that had touched personal data. It does not by itself mean raw personal data was sent; see the raw value check.
  • The raw value check uses fixed patterns (SSN, AWS key, GitHub token, email, phone, card number, private key). Names, addresses and free text personal data are not matched by these patterns. Run with --deep-scan to also use the Presidio detectors (slower, more false positives).
